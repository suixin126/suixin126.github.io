## 四、技术问题应对（针对技术面试官）

### 4.1 为什么选择 Vue 3 而不是 React？

"选择 Vue 3 主要基于以下几点考虑：

第一，**学习曲线**：Vue 3 的模板语法更接近传统 HTML，上手更快，Composition API 也比 React Hooks 更容易理解，没有闭包陷阱。

第二，**性能**：Vue 3 的响应式系统基于 Proxy，相比 React 的 diff 算法性能更好，而且 Vue 3 的编译时优化（静态提升、Tree Shaking）让运行时性能更优。

第三，**生态**：Vue 3 的全家桶（Vue Router、Pinia）都是官方维护，配合更紧密，而 React 生态由社区主导，选择成本高。

第四，**TypeScript 支持**：Vue 3 用 TypeScript 重写，对 TS 的支持非常好，而 React 的 TS 支持需要额外的类型定义。"

### 4.2 Composition API 的优势是什么？

"Composition API 有三大优势：

第一，**逻辑复用**：相比 Options API 的 mixins，Composition API 的组合式函数（Composables）更清晰，不会出现命名冲突和来源不明的问题。

第二，**代码组织**：可以将相关逻辑（如状态、方法、计算属性）组织在一起，而不是分散在 data、methods、computed 中，代码可读性更强。

第三，**类型推断**：Composition API 配合 TypeScript，类型推断更准确，减少了手动类型注解的工作量。

在这个项目中，我封装了 `useGamesStorage`、`useBlogData` 等多个 Composables，实现了逻辑复用。"

### 4.3 Pinia 和 Vuex 的区别？

"Pinia 是 Vue 3 官方推荐的状态管理库，相比 Vuex 有以下优势：

第一，**TypeScript 支持**：Pinia 天然支持 TypeScript，类型推断准确，而 Vuex 需要复杂的类型定义。

第二，**API 简洁**：Pinia 没有 mutations，只有 state、getters、actions，简化了状态管理。

第三，**模块化**：Pinia 天然支持模块化，每个 Store 独立，而 Vuex 需要手动划分 modules。

第四，**体积更小**：Pinia 的包体积只有 Vuex 的一半左右。

在这个项目中，我使用 Pinia 管理博客文章、游戏数据等全局状态，配合持久化插件实现数据自动保存。"

### 4.4 如何优化首屏加载速度？

"我在项目中使用了多种优化手段：

第一，**路由懒加载**：所有页面组件使用动态 import，按需加载，减少初始包体积。

第二，**代码分割**：Vite 自动进行代码分割，将第三方库单独打包，利用浏览器缓存。

第三，**图片懒加载**：使用 Intersection Observer API 实现图片懒加载，只加载可视区域图片。

第四，**组件懒加载**：非首屏组件（如游戏模块）使用 defineAsyncComponent 延迟加载。

第五，**Tree Shaking**：确保生产环境移除未使用的代码，减少包体积。

第六，**CDN 加速**：将静态资源部署到 CDN，提升加载速度。

通过这些优化，首屏加载时间控制在 1 秒以内。"

### 4.5 TypeScript 的好处是什么？

"TypeScript 带来了五大好处：

第一，**类型安全**：在编译阶段就能发现类型错误，减少运行时 bug。在这个项目中，TS 严格模式帮我发现了 100+ 潜在问题。

第二，**更好的 IDE 支持**：类型推断让代码提示更准确，开发效率提升 30% 以上。

第三，**代码可维护性**：类型定义相当于文档，新成员接手项目更容易理解。

第四，**重构信心**：类型系统保证重构的安全性，修改代码时能快速发现影响范围。

第五，**团队协作**：类型定义是团队成员之间的契约，减少沟通成本。

在这个项目中，TypeScript 的类型覆盖率达到 95% 以上，any 类型使用率不到 5%。"
